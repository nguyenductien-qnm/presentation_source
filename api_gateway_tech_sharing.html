Architecture Decision Tree

Requirement Nào KHIẾN HTTP API Không Đáp Ứng Được?

Đừng đọc thuộc lòng tính năng. Hãy bắt đầu từ yêu cầu hệ thống thực tế.

Khi nào REST API là lựa chọn phù hợp?

  • 🔥 Hệ thống phụ thuộc vào AWS WAF Association trực tiếp ở Gateway?
  • 🔑 Cần API Keys / Usage Plans cho B2B Consumer metering?
  • 🔄 Cần Programmable VTL Payload Transformation?
  • 🏢 Cần Private API Endpoint trong VPC?
  • ⚡ Cần Caching / Canary Release / Custom 4xx/5xx Responses?

Khi nào nên ưu tiên chọn HTTP API?

  • ✨ Serverless Microservices tiêu chuẩn (Proxy sang Lambda/HTTP).
  • 💰 Ưu tiên chi phí request thấp hơn & đơn giản hóa kiến trúc.
  • ⚡ Ưu tiên API Gateway đơn giản và lightweight.
  • 🔐 Dùng Native JWT / OIDC Authorizer (Auth0, Okta, Cognito).

Bảng So Sánh: REST API vs HTTP API

Minh chứng kỹ thuật chi tiết chuẩn hóa theo AWS Official Docs.

Tiêu chí REST API (Feature-rich) HTTP API (Lightweight / Cost-efficient)
Chi phí base $3.50 / 1M requests* $1.00 / 1M requests*
Payload Transformation VTL Mapping Templates — programmable JSON payload transformation Parameter Mapping — header/query/path & selected body properties (Không VTL)
Auth & Authorization IAM, Cognito User Pools, Lambda Authorizer IAM, JWT Authorizer (OIDC), Lambda Authorizer
Throttling & Quotas API Keys + Usage Plans + per-consumer throttling Account + Route-level throttling (HTTP API capability limitation: No API Keys / Usage Plans)
AWS WAF Support ✅ Native WebACL Association ❌ Không có native integration
Built-in Caching ✅ Có (Cache tại Stage/Method) ❌ Không
Request Validation ✅ Có (Parameters & JSON Schema) ❌ Không
Private API Endpoint ✅ Có (VPC Endpoint) ❌ Không (Chỉ có Regional Endpoint)
Automatic Deployment ❌ Không ✅ Có (Default)
Canary Deployment ✅ Có ❌ Không
Custom Gateway Responses ✅ Có (Custom 4xx/5xx responses) ❌ Không

💡 Practical Decision Rule: Ưu tiên chọn HTTP API làm mặc định. Chỉ chọn REST API khi hệ thống phụ thuộc vào capability chỉ có trên REST API.

Capability Deep-Dive

Transformation: VTL Mapping vs Parameter Mapping

Parameter Mapping ≠ VTL. Limited parameter transformation vs Programmable template transformation.

REST API: VTL Mapping Template

// VTL Mapping Template (REST API) { "userId": "$input.path('$.user_id')", "items": [ #foreach($item in $input.path('$.items')) { "code": "$item.id", "qty": $item.count }#if($foreach.hasNext),#end #end ] }

• Programmable request/response transformation using VTL.
• Can construct a new payload shape from incoming request.

HTTP API: Parameter Mapping

// Parameter Mapping Rules (HTTP API) request.header.X-User-Id ← $request.body.userId request.querystring.page ← $request.querystring.p overwrite:statuscode ← 200

• Trích xuất / đổi tên Header, Query, Path & Selected body properties.
• ❌ Không hỗ trợ REST API-style programmable body transformation bằng VTL.

Đặc tính REST API: VTL Mapping Template HTTP API: Parameter Mapping
Bản chất Engine Full Template Language (Velocity Engine) Limited Parameter Transformation Engine
Logic & Vòng lặp ✅ Có (Vòng lặp #foreach, rẽ nhánh #if) ❌ Không có programmable logic / loop / conditional template
Rebuild JSON Body ✅ Arbitrary Rebuild JSON Body ❌ Không thể arbitrary rebuild JSON body

API Security Architecture

API Security Architecture & Identity Abstraction

Phân rã AuthN, AuthZ, Abuse Protection & Bản chất API Key vs User Identity.

1. API Key (Usage / Metering)

Consumer / Usage Identifier

API Key = Application/consumer identifier for usage control

  • • Đại diện cho Client Application / Partner / Tenant.
  • • Ví dụ: Tenant A (10,000 Users) ➔ Có thể dùng 1 API Key cho một integration.
  • • Đo đếm Quotas & Usage Plans.
2. JWT / Cognito (AuthN / AuthZ)

User Identity

Who is this user & what can they do?

  • • 1 User ➔ 1 JWT Token riêng biệt.
  • • AuthN: JWT / OIDC / Cognito.
  • • AuthZ: Coarse-grained Scopes (Gateway) ➔ Fine-grained (Application).
3. AWS WAF (Layer 7 Protection)

Abuse Protection

Web ACL Firewall & Rate Rules

  • • Layer 7 Web ACL Managed/Custom Rules.
  • • Chống Bot, SQLi, XSS, IP Rate-based Rules.
  • • (Khác với APIGW Token Bucket Throttling).

⚠️ Misconception phổ biến: API Key không phải là Authentication hay Identity Assurance!

07 — API Security Architecture
Integration Mechanics

Proxy vs Non-Proxy Integration

Khi Nào Integration Error Có Thể Biến Thành HTTP 200 OK?

⚡ Lambda Proxy Integration

Proxy Integration loại bỏ nhu cầu cấu hình Integration mapping thủ công; Gateway chuyển request theo proxy event model và nhận response theo Lambda proxy contract.

// Lambda Proxy Response Contract { "statusCode": 200, "headers": { "Content-Type": "application/json" }, "body": "{\"message\": \"Success\"}" }

⚙️ Non-Proxy Integration (Custom VTL)

Non-proxy integration có thể tạo "silent failure" nếu error mapping được cấu hình sai.

⚠️ Configuration Failure: Backend error ➔ Không match selectionPattern ➔ Rơi vào Default Integration Response ➔ Nếu response đó map tới Method Response 200, Client sẽ nhận HTTP 200!

🔗 AWS Developer Guide: Lambda Proxy Output Format | Custom Non-Proxy Error Handling

09 — 502 Diagnostic Playbook
Production Error Philosophy

Sự Tương Phản: Lỗi Ồn Ào (502) vs Lỗi Im Lặng (200)

Triết lý vận hành hệ thống lớn trên Production.

📢 LỖI ỒN ÀO (502 Bad Gateway)

  • ⚡ Hành vi: Trả mã 5xx lập tức ngắt kết nối.
  • 🚨 Giám sát: Monitoring & Alert nhảy ngay.
  • 🛠️ Xử lý: Dev khoanh vùng và fix dựa trên error traceback.

🔕 LỖI IM LẶNG (200 OK Malformed)

  • 👻 Hành vi: Client nhận HTTP 200 dù business operation thực tế thất bại.
  • 🙈 Giám sát: Monitoring dựa trên HTTP status có thể bỏ sót lỗi.
  • 🩸 Hậu quả: Tích tụ dữ liệu hỏng mà hệ thống ngỡ là thành công.

🔍 Production Observability Takeaway: Đừng chỉ monitor duy nhất HTTP Status Code! Luôn liên vết (Correlate): APIGW Access Log ➔ Lambda Log ➔ Request Correlation ID ➔ Business Outcome.

Deployment Architecture

API Gateway Deployment ≠ Application Deployment

Kiến trúc API Configuration Snapshot, Stage Variables & Lambda Alias Routing.

1. API Gateway: Configuration Snapshot

Sửa Route/Method trên Console ➔ Bắt buộc bấm Deploy API Stage mới tạo ra API configuration snapshot được stage phục vụ.

⚠️ Console configuration ≠ Deployed stage configuration. Quên deploy stage sẽ khiến stage phục vụ deployment cũ.

2. Lambda Alias Routing Pattern

Production Risk: Trỏ API Gateway trực tiếp vào $LATEST. Sửa code Lambda ➔ Production bị ảnh hưởng tức thì!

💡 Một Pattern Hữu Ích: Dùng APIGW Stage Variable ${stageVariables.lambdaAlias} trỏ tới Lambda Alias (trỏ vào Lambda Version). Khi chỉ promote Lambda version/alias, không cần tạo deployment mới cho API Gateway.
11 — Deployment Architecture
Optional Architecture Patterns

Beyond Lambda: Where API Gateway Can Integrate

API Gateway không nhất thiết phải trỏ tới Lambda. Các kịch bản tích hợp mở rộng kiến trúc.

1. Direct AWS Service (Lambda-less)

⚡ Loại bỏ Lambda khỏi đường request khi ghi thẳng DynamoDB/SQS từ API Gateway bằng VTL ➔ Giảm một hop network và chi phí compute Lambda.

2. Async Offloading (Queue & Worker)

🛡️ Trả ngay 202 Accepted cho Client, đẩy task nặng vào SQS Queue cho Worker ➔ Tránh phụ thuộc vào synchronous API timeout cho long-running jobs.

3. Security Topology (WAF ➔ APIGW ➔ JWT)

🔒 Topology nhất quán: Internet ➔ AWS WAF (Abuse Protection) ➔ API Gateway ➔ JWT Authentication ➔ Backend Services.

4. VPC Link (Private Integration)

🏢 Connect an toàn từ API Gateway qua VPC Link tới Private Integration (ALB/ECS Fargate) nằm giấu kín trong mạng nội bộ.

Lab Phase 1

Phase 1 — First API & The Deploy Trap

Tái tạo tình huống Console configuration ≠ Deployed stage configuration.

• Tạo REST API ➔ Route GET /items ➔ Map tới Lambda Handler.
• Test trên Console ➔ Thành công 200 OK.
• Gọi qua Stage URL ➔ Route/resource mới chưa có trong deployment đang phục vụ ➔ Request không đi tới configuration mới (Trong setup lab này quan sát thấy response 403 Forbidden).
• Khắc phục: Bấm Deploy API ➔ Chọn Stage dev ➔ Gọi lại thành công.

Lab Phase 2

Phase 2 — Breaking the Proxy Contract (502)

Cố tình làm gãy hợp đồng Proxy để kích hoạt lỗi 502 Bad Gateway.

• Sửa Lambda return chuỗi thô return "Hello".
• Gọi API ➔ Nhận ngay lỗi 502 Bad Gateway.
• Mở CloudWatch Log của Lambda ➔ Dòng log Success 200.
• Khắc phục: Trả response đúng format của Lambda Proxy Integration contract { statusCode: 200, body: "..." }.

Lab Phase 3

Phase 3 — Non-Proxy Integration & VTL

Xây dựng luồng biến đổi Payload bằng VTL Template.

• Chuyển API sang Non-Proxy Integration.
• Viết VTL Mapping Template đổi `user_id` thành `userId`.
• Cấu hình Integration Response bắt Regex lỗi.
• Kiểm tra Payload được transform sạch sẽ trước khi tới Backend.

17 — Lab Phase 3
Lab Phase 4

Phase 4 — Stage Variables + Lambda Alias

Cấu hình định tuyến động giữa các Lambda Versions qua Lambda Alias.

• Tạo 2 Lambda Version (Version 1 & Version 2) ➔ Gán Alias :dev và :prod trỏ vào Version tương ứng (Alias không chứa code, trỏ vào Version).
• Khai báo Stage Variable lambdaAlias = dev.
• Map ARN Target: arn:aws:lambda:...:my-func:${stageVariables.lambdaAlias}.
• Thử nghiệm chuyển Alias trỏ sang Version mới không làm gián đoạn Stage :dev.

18 — Lab Phase 4
Lab Phase 5

Phase 5 — API Keys, Usage Plans & Throttling

Thiết lập Hạn ngạch & Giới hạn Rate Limit cho Client.

• Tạo API Key ➔ Gán vào Usage Plan (Rate: 5 req/s, Burst: 10).
• Bật `API Key Required = true` trên Method Request.
• Gọi thử không truyền Header `x-api-key` ➔ Dính 403 Forbidden.
• Bắn burst requests dồn dập ➔ Observe throttling behavior (có thể nhận 429 Too Many Requests khi vượt limit).
